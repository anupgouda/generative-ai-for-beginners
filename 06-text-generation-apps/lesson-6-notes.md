# Lesson 6 — Text Generation Applications

## 1. What Is a Text Generation Application?

A text generation application uses an LLM to generate content based on the user's input.

Unlike traditional command-based or UI applications, where actions are usually predefined, a text generation application can produce dynamic responses based on natural-language input.

For example:

A traditional application might have a button that always performs the same operation.

An AI Study Buddy can generate a different explanation or exercise depending on the student's topic.

---

## 2. Benefits of Text Generation Applications

The main benefits include:

- Dynamic and personalized content.
- Natural-language interaction.
- Ability to handle many different types of requests.
- Automation of tasks such as writing, summarizing, explaining, and generating ideas.
- Responses that adapt to the user's input.

Text generation applications are more flexible because users can communicate using natural language instead of being restricted to predefined commands.

---

## 3. Integrating an LLM into an Application

The lesson presents two main approaches:

### 1. Use an API

The application constructs a request containing the prompt and sends it to a hosted LLM through an API.

The generated response is then returned to the application.

### 2. Use a Library

Libraries encapsulate API calls and make it easier for developers to communicate with LLMs.

Examples mentioned in the lesson include:

- `openai`
- LangChain
- Semantic Kernel

The `openai` Python library provides a convenient way for Python applications to communicate with OpenAI models.

## 4. Prompts, Responses, and Tokens

### Prompt

A prompt is the input or instruction sent to the LLM.

Example:

```text
Explain Python loops.
Response

A response is the text generated by the LLM based on the input.

Tokens

Tokens are smaller pieces of text processed by the model.

Words can be represented by one or several tokens depending on the tokenizer.

The basic flow is:

Prompt
   ↓
Tokens
   ↓
LLM
   ↓
Generated response
   ↓
Tokens
5. Using the OpenAI Python Library

The openai Python library allows applications to communicate with OpenAI models programmatically.

A basic pattern is:

from openai import OpenAI

client = OpenAI(api_key="...")

The Responses API can then be used to generate text:

response = client.responses.create(
    model="gpt-5-mini",
    input="Explain Python loops.",
    store=False
)

print(response.output_text)

The exact model or deployment name depends on the platform being used.

6. Protecting API Keys

API keys are secret credentials.

They should not be hard-coded directly into source code because they could accidentally be exposed or committed to GitHub.

Instead, environment variables can be used.

For local development, a .env file can contain:

OPENAI_API_KEY=your_api_key_here

Python can load the value using python-dotenv:

from dotenv import load_dotenv
import os
from openai import OpenAI

load_dotenv()

api_key = os.getenv("OPENAI_API_KEY")

client = OpenAI(api_key=api_key)

The .env file should be added to .gitignore:

.env

The security principle is:

.env
   ↓
Environment variable
   ↓
Python application
   ↓
LLM API

The actual secret should never be committed to GitHub.

7. max_output_tokens

max_output_tokens limits the maximum amount of output the model can generate.

Controlling output tokens is useful because it can:

Prevent unnecessarily long responses.
Control API costs.
Improve response time.
Keep outputs within the application's expected format.

Example:

response = client.responses.create(
    model=deployment,
    input=prompt,
    max_output_tokens=100,
    store=False
)

For example, a short coding exercise does not need thousands of output tokens.

8. Temperature

Temperature controls the variation or randomness of generated output.

Generally:

Lower temperature → more predictable and consistent responses.
Higher temperature → more varied and creative responses.

For example:

Technical explanations → lower variation can be useful.
Structured output → lower variation can be useful.
Brainstorming → more variation can be useful.
Creative ideas → more variation can be useful.
Important 2026 Model Consideration

The lesson notes that current reasoning models such as GPT-5 do not support temperature in the same way as models that expose temperature.

Therefore, an application should first check whether the specific model and API support the parameter.

For reasoning models, prompt engineering and reasoning controls may be used instead.

The engineering principle is:

Do not assume that every model supports the same generation parameters.

9. How the Recipe Generator Evolved

The recipe generator was gradually improved throughout the lesson.

Stage 1 — Fixed Prompt

Initially, the application used a fixed prompt to generate recipes.

Stage 2 — User Input

The application was modified to allow the user to specify:

Number of recipes.
Ingredients.

For example:

No of recipes: 3
Ingredients: milk, strawberries

The prompt could then be constructed dynamically:

prompt = f"Show me {no_recipes} recipes for a dish with the following ingredients: {ingredients}. Per recipe, list all the ingredients used"
Stage 3 — Filtering

A filter was added so users could specify requirements such as:

vegetarian
vegan
gluten-free
no milk
Stage 4 — Shopping List

A second prompt was introduced to generate a shopping list based on the recipes produced by the first prompt.

The previous response was included as context:

old_prompt_result = response.output_text

prompt = "Produce a shopping list for the generated recipes and please don't include ingredients that I already have."

new_prompt = f"{old_prompt_result} {prompt}"

The application then generated a separate shopping list.

The overall progression was:

Fixed prompt
    ↓
User input
    ↓
Filtering
    ↓
Follow-up prompt
    ↓
Shopping list

This demonstrates how a simple LLM application can gradually become a more practical product.

10. One Prompt vs Multiple Prompts

With one prompt, the application provides all necessary information and instructions at once and generates one response.

With multiple prompts, a complex task can be divided into stages.

For example:

Prompt 1
Generate a study explanation.
        ↓
Prompt 2
Use the explanation to create an exercise.
        ↓
Prompt 3
Use the explanation and exercise to create the solution.

Multiple prompts can make complex workflows easier to control because each stage can focus on a specific task.

The recipe generator demonstrates this approach by using the first generated recipe response as context for the shopping-list prompt.

Task	Temperature	Token Strategy	Reason
Explain a Python concept	Low / deterministic where supported	Moderate limit	Clear and consistent explanation
Generate coding exercise	Low–medium where supported	Moderate limit	Useful variation while keeping exercises focused
Generate creative project ideas	Higher variation where supported	Larger limit	Creativity and variety are useful

For models that support temperature:

Lower temperature → more predictable output.

Higher temperature → more varied output.

For current reasoning models such as GPT-5, the application's code should first verify whether temperature is supported rather than assuming it is available.

4. Handling Unpredictable Output

The application can:

Use structured prompts.
Specify the expected output format.
Use lower variation where supported for technical tasks.
Validate structured outputs.
Test generated answers.
Ask the model to state uncertainty instead of inventing information.

For example, if the application expects JSON, it should validate that the returned content is valid JSON before using it.

6. Testing the Generated Answer

A test set should contain different topics, student levels, and edge cases.

Important evaluation criteria include:

Accuracy

Is the explanation technically correct?

Relevance

Does it answer the requested topic?

Clarity

Can the intended learner understand it?

Instruction Following

Did it generate the requested number of exercises?

Code Correctness

Does generated code actually work?

Consistency

Does the application behave reliably?

Safety

Does it avoid inappropriate or harmful responses?

A combination of automated tests and manual review can be used to evaluate the application.
